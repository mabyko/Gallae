# UC-51 · 최근 Discard 복구

> 우선순위: P1

| 항목 | 내용 |
| --- | --- |
| 사용자 목표 | Gallae에서 방금 Discard한 미커밋 파일 내용을 되찾는다. |
| 시작 조건 | 현재 작업 폴더에 복구 가능한 최근 Discard 기록이 있다. |
| 진입점 | Repository Workspace 상단의 `Restore Last Discard` |
| 완료 상태 | Discard 직전 파일 내용과 권한을 복원하고 최신 상태를 보여 준다. |

## 정상 흐름

1. 파일·hunk·선택 줄 Discard 전에 지원 대상의 원본을 보관한다.
2. 원본을 보관한 작업 폴더에 복구 버튼을 표시하고, Discard 결과가 예상한 내용과 일치할 때 활성화한다.
3. 사용자가 복구를 실행하면 작업 폴더, branch·HEAD, 해당 파일의 index와 Discard 이후 파일 상태를 다시 확인한다.
4. 원래 파일 내용과 권한을 복원하고 Repository를 새로 읽는다. 성공한 복구 기록은 지운다.

## 지원 범위와 대안 흐름

- 앱 전체에서 최근 한 번만 보관하며 앱 종료 뒤에는 남지 않는다. 다음 Discard는 이전 기록을 대체한다.
- 기존 일반 파일과 index 버전이 각각 16 MiB 이하인 경우를 지원한다. 보관하는 전후 파일 내용은 합계 최대 32 MiB다.
- 삭제된 파일·심볼릭 링크·큰 파일은 복구 대상이 아니다. Discard 확인에서 이 범위를 알린다.
- 진행 중인 Git 작업에서는 복구 기록을 만들지 않는다. 예상 결과를 검증하지 못하면 원본만 보관하고 복구 버튼은 비활성화한다.
- linked Worktree에서도 해당 작업 폴더를 기준으로 복구한다. 다른 폴더를 열면 복구 버튼을 숨기며, 단순 파일 선택 변경은 기록을 지우지 않는다.
- 이후 파일을 편집·삭제·교체했거나 branch·HEAD·해당 index가 바뀌었다면 복구를 거부하고 오류를 표시한다. 외부 변경을 덮어쓰지 않는다.
- 복구를 거부한 경우 원본 사본은 다음 Discard나 앱 종료 전까지 유지한다.
- 파일 교체에 실패하면 오류를 표시하고 복구 기록을 유지한다.

## 완료 확인

- 부분 Stage 상태에서도 index와 HEAD는 바뀌지 않는다.
- hunk·선택 줄 Discard의 복구도 Discard 직전 파일 전체를 복원하며, 이후 편집이 있으면 실행하지 않는다.
- 앱의 일반 Undo/Redo나 Reflog 복구와 혼동하지 않도록 최근 Discard 전용으로 표시한다.
