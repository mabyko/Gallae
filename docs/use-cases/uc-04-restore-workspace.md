# UC-04 · 마지막 Workspace 복원

> 우선순위: P0

| 항목 | 내용 |
| --- | --- |
| 사용자 목표 | 앱을 다시 열고 하던 위치에서 계속한다. |
| 시작 조건 | 이전에 Active Repository가 저장되어 있다. |
| 진입점 | 일반적인 앱 실행 |
| 완료 상태 | 유효한 Workspace가 복원되거나 Repository Library에 복구 경로가 나타난다. |

## 정상 흐름

1. Gallae가 저장된 Repository 위치와 접근 가능 여부를 확인한다.
2. 화면 구조를 복원하고 Git 데이터는 새로 읽는다.
3. 현재 Changes에서 예측 가능한 기본 항목을 선택한다.

## 대안 흐름

- Repository가 이동하거나 삭제됐다면 Repository Library로 이동해 기존 위치와 실패 원인을 표시한다.
- 저장된 위치를 읽을 수 없다면 다시 찾는 경로를 제공한다.
- 사용자는 Repository를 다시 찾거나 최근 항목에서 제거할 수 있다.
- 복원할 Repository가 없으면 오류 대신 Repository Library의 빈 상태로 이동한다.
- 한 번 실패한 위치를 다음 실행마다 자동으로 다시 열지 않는다. 사용자가 다시 연결하거나 다른 Repository를 열면 복원 대상을 갱신한다.

## 완료 확인

- 화면 복원과 Git 데이터 새로고침을 구분한다.
- 마지막 성공 상태를 보여 줄 때는 최신 정보가 아님을 표시한다.
- 복원 실패가 저장된 다른 Repository 정보를 지우지 않는다.
